# GPU optimisation pass: after (vs perf-gpu-before.txt)

Machine: AMD Vega 8 laptop, headless Chrome (ANGLE D3D11), tools/scenarios/areaperf.mjs with PERF=1 (vsync off), dpr 1.
Baseline = commit 0a624b8 (a private copy of it), after = this branch. The two were run alternately (base, new, base, new)
so drift in GPU clocks and in the load from other agents hits both sides. Other agents were running the game headless
on the same GPU through the whole session, so per-frame GPU ms is noisy (a single run can be 2x off); "p10" is the
10th-percentile frame of the better run, the figure least disturbed by contention. Draw calls and triangles are
deterministic (one frame, main pass + shadow pass).

  desktop low  = 1280x720, low tier (the phone/integrated-GPU default), lite counts (2 runs each side)
  mobile low   = --mobile (844x390 phone viewport), low tier (2 runs each side)
  desktop high = GFX=high: High profile (full crowd/traffic counts, 950 m view, 2048 shadow map, MSAA + bloom + grade)
                 (1 run each side; Temple Bar / Christ Church medians in that run were disturbed, see p10)

## What changed (all pure efficiency: High looks the same; the only Low/Battery-saver-only change is marked)

1. Road markings (src/world/roads.js). The whole city's markings were ONE 347k-triangle mesh drawn every frame, with no
   culling: the kerb-side double yellow lines were built from the 0.5 m test samples of clipToOwnRoad, i.e. one quad
   per half metre of kerb. Collinear samples are now dropped after the test (same lines, ~14x fewer quads), and the
   markings are split into 600 m blocks so off-screen blocks are culled. 347k -> ~15k triangles for the whole
   city. Biggest single win, and it scaled with the map.
2. Trees (src/world/chunks.js packedInstances, src/world/trees.js). The Blender trees (1-2.5k tris each) were in 250 m
   blocks, each block drawn whole in the main pass and in the shadow pass. Now each species is one instanced mesh for
   the view and one for the shadow map, repacked every frame with just the trees inside the camera frustum / the
   shadow camera's box. Draw calls per species are constant however big the map; triangles follow the screen.
   (Shadow-only meshes are shown only during the shadow pass: installShadowOnly wraps renderer.shadowMap.render.)
3. Parked cars (src/game/fleet.js, traffic.js). All parked cars in the city lived in the moving-car instanced meshes
   (frustumCulled = false), so every one was drawn every frame in both passes. They still share those meshes (no new
   draw calls) but only the ones in view or within 90 m of the player (shadow range) are packed in each frame.
4. Lamps (src/world/props.js). Modern pole + arm + head (3 meshes), heritage frame + lantern (2), wall frame + lantern
   (2) are now one mesh per kind with one material: paint in vertex colours, roughness / metalness / emissive mask from
   a 2-texel lookup, lantern glass doubled with flipped faces instead of side: DoubleSide. 7 -> 3 draw calls per block.
   Same colours, finish and night glow. Low / Battery saver only: lamps no longer cast the sun shadow (as the rest of
   the street furniture already didn't in the lite profile).
5. Signal lenses (src/world/furniture.js): one city-wide 42k-triangle instanced mesh -> 500 m blocks (culled), and the
   hidden back cap of each lens dropped.
6. Water glow (src/render/waterglow.js): only reflections within the view distance take a slot (was all of them,
   updated every frame at night; this grows with every lamp near water on the bigger map).
7. Lamp point lights (props.js update): nearest-3 by a single linear pass instead of map + sort of every lamp in the
   city 4x a second.
8. Traffic respawn (traffic.js): recycled cars pick from edges 125-315 m from the player (cached, refreshed every 40 m)
   instead of random edges anywhere; on a 2.5-3x map the old 12 random tries mostly missed, stranding cars far away.
9. Static objects (chunks.js, buildings.js, roads.js markings): matrixAutoUpdate = false, so the per-frame scene-graph
   update no longer recomposes their matrices (793 -> 388 auto-updating objects).
10. Baked maps (src/render/lamplight.js, groundao.js): resolution becomes coarser only if the map exceeds 4096 m, so
    the textures never exceed the 4096 px limit many phone GPUs have (identical at today's size).
11. reflect.js: the program cache key includes the glass expression (two materials with different expressions could
    otherwise share one compiled program).
12. tools/scenarios/areaperf.mjs: GFX=high / EVENING=1 options, per-frame sums over all render() calls (the High tier
    has several passes), p10 GPU time, and GPU timer queries are deleted after reading (they leaked).

Checked and left alone: the building facade shader is the largest single fill cost (hiding buildings saves 5-9 ms at
Temple Bar) but its work is per pixel of wall on screen, already LODs out window detail with distance, and any cut
would change looks. The shadow pass costs 2-5 ms (low tier) and is re-rendered every frame on purpose (car shadow);
trees and parked cars in it are now culled to the shadow box. Light pools are hidden by day and are cheap at night
(additive, 12 m quads, ~1 ms). Festoons / baskets are already batched into a few static meshes and don't cast shadows.

## Costs that scale with the map (main is now ~1.6x wider and ~2x taller than this baseline: ~3.3x the bounds area)

Fixed on this branch: road markings (were one un-culled mesh), trees (block-drawn, both passes), parked cars (all drawn
every frame), signal lenses (one city-wide mesh), water-glow update loop, lamp nearest-light sort, traffic respawn
picking, static matrix updates, lamp-light / ground-AO texture size cap.

Still to do, by priority (sizes for the ~2.5x map at today's resolutions):
1. Kerb distance field (roads.js: G = 1 m over the whole bounds). Three Float32 arrays of NX*NZ during the build
   (field, scratch, rd) = ~110 MB transient, a 1 m half-float texture (18 MB on the GPU) and a width that will pass
   4096 texels on the next widening, where phones with a 4096 limit fail to upload it. Recommendation: compute the
   field per 256 m tile only where roads are (most of the map is buildings/parks), store tiles in a texture array or
   an atlas, and free scratch/rd after the build. Short term: reuse one scratch array and free it.
2. Building occupancy grid (buildings.js: Uint8 at 0.5 m over the bounds): ~37 MB at the new size, 4x the cost of a
   1 m grid. Recommendation: 1 m cells, or a Map of 64 m tiles allocated only where lots are placed; drop it after
   the build.
3. Layout / minimap canvases (ground.js layoutCanvas at 1.6 px/m, hud.js mini at 1.5 px/m): ~6500x3600 RGBA
   (~94 MB) plus a ~85 MB copy. iOS Safari refuses canvases over ~16.7 Mpx, so the minimap will go blank on iPhones
   at the new size. Recommendation: draw the minimap per 512 px tile on demand (or at <= 1 px/m, capped to 4096 px).
4. Lamp-light and ground-AO bakes: capped at 4096 px on this branch, but each is still W*H floats on the CPU while
   baking (~37 MB each at 4 km x 2.3 km). Recommendation: bake per tile / only where roads are; free the Float32.
5. World build time: buildings, pavements (ExtrudeGeometry per block), markings, landmark batching are all built at
   load for the whole map (~18-25 s here under load). Recommendation: build per district chunk and stream the far
   ones in after the first frame (the chunk grids already exist); at minimum yield between districts so the intro
   doesn't freeze.
6. people.js refreshNearby: filters every footpath lane (with a per-point distance test) each 25 m the player moves:
   O(all lanes). Recommendation: bucket lanes into the 40 m road hash (world.segsNear) once and query nearby cells.
7. Buildings: one InstancedMesh per 450 m chunk; all ~14k (soon ~40k) boxes live in GPU memory with 60-byte
   per-instance attributes. Fine for draw calls; if memory bites, drop far chunks beyond the 600/950 m view.
8. Collision segments (collision.js, 75k segments, 16 m hash): memory grows linearly (~3x) but lookups stay local.
   OK as is.
9. Audio junction list (audio/city.js) and signal heads update loop: linear over all junctions/heads per frame, but
   small (hundreds). Bucket by 250 m cells if the junction count passes ~2k.
10. Draw calls from chunk grids (lamps, furniture, chimneys, buildings: 450-600 m blocks): the number of visible
    blocks is set by the view distance, not the map size, so this stays flat.
